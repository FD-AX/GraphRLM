Проблема

  • LLM выдаёт правдоподобный вердикт, даже когда собранные доказательства неполны.
  • Точность ответа и полнота доказательной базы — разные вопросы; стандартные метрики (EM/F1) меряют только первое.
  • False completion — система считает дело закрытым, не собрав всю цепочку — главный невидимый режим отказа RAG-систем.

Постановка GraphRLM

Полнота доказательств — первоклассная задача: система обязана знать, чего она ещё не знает, и не давать вердикт без полного набора.

Архитектура

1. Графовый слой (BERT, без обучения)

  • Узлы и связи графа вербализуются и кодируются одним энкодером (multilingual MiniLM)
  • Типизированные связи: сущности, события, evidence-споты, слоты недостающих доказательств
  • Аудит полноты — дёшево, без LLM

2. RLM discovery (gap-driven)

  • LLM-контроллер запускается только когда аудит нашёл пробел
  • Действия: expand / reformulate (поиск-прыжок) / verify / answer
  • Гарды полноты: декомпозиция на хопы, минимум свидетельств до ответа

Бенчмарк: MuSiQue evidence completeness

  • 500 кейсов валидации, стратифицированы 200/150/150 по 2/3/4 хопам; 20 параграфов-кандидатов на вопрос, gold-цепочка supporting-параграфов.
  • Complete coverage = 1, только если найдены все gold-параграфы кейса. Плюс evidence recall, answer F1/EM.
  • Равный бюджет извлечения (top-5) для всех локальных армов; один энкодер на всех.
  • Воспроизводимость: версионируемые конфиги, run-манифесты (commit SHA, хеши, токены), покейсовые JSON в репо, дашборды Grafana.

Результат 1: плато безграфовых методов

Метод (top-5, без обучения)RecallCoverage
Лексический поиск0.3750.068
Dense bi-encoder0.5860.210
Cross-encoder — исчерпывающий матчинг всех пар0.6000.206
MDR-style итеративный re-querying (+ развёртка семейства)0.5380.208–0.226
Граф-навигатор (та же модель, те же 5 параграфов)0.6230.298

Всё «хождение по косинусам» — одношаговое, исчерпывающее, итеративное — упирается в плато полноты ~0.21. Связанность пробивает его без единого LLM-вызова: +8.8 п.п. (52W/8L, p << 0.001).

Почему плато — фундаментально

  • Параграфы дальних хопов не похожи на вопрос — ни лексически, ни в эмбеддинге. Идеальный матчинг это не лечит: cross-encoder с неограниченным парным сравнением = dense (46W/48L, ничья).
  • Необученное обновление запроса (MDR-форма) монотонно жертвует recall: развёртка anchor-веса 1.0 → 0.5 даёт 0.586 → 0.518 (при 1.0 — точная копия dense, проверка пайплайна).
  • Достают их только мосты: типизированные связи через bridge-сущности между параграфами — то, чего нет в векторе вопроса.

Полноту даёт связанность, а не качество сравнения.

Честная аблация: а нужен ли граф контроллеру?

Система (тот же контроллер и бюджет)CoverageF1Токенов/кейс
text-RLM — dense-фронтир, без графа0.8500.571~121k
graph-RLM — типизированный фронтир0.7330.621~68k
  • При 20 кандидатах контроллер видит весь пул каждый шаг — и пробивает плато без графа, но за ×1.8 цены.
  • Граф здесь покупает эффективность (68k против 121k токенов/кейс); сдвиг F1 (+5 п.п., 10W/9L) при n=60 незначим.
  • «Показать всё» не существует на открытом корпусе — дистракторный сеттинг систематически занижает ценность графа. Open-corpus — следующий эксперимент.

Ниша: completeness-first постановка, гарантия отсутствия false completion, gap-driven экономика (дорогой цикл — только по триггеру дешёвого аудита).

Инженерная база

  • Типизированный рантайм: Pydantic-модели, 71 тест
  • Провенанс эмбеддингов: энкодер, токенайзер, пулинг, хеши контента
  • Чекпоинты и шардирование прогонов (5 параллельных потоков, резюмирование)
  • Конфиги опубликованных строк + run-манифесты (commit SHA, хеш конфига, токены)
  • Результаты — JSON в репозитории, покейсово
  • Grafana + PostgreSQL: дашборд полноты, переключение прогонов v1/v2

Весь бенчмарк (6 армов × 500 кейсов + 4 аблации): ~$21 и два дня работы.

Что дальше

  • Open-corpus реплика: общий индекс 10 000 параграфов вместо 20 кандидатов — режим, где «показать всё» невозможно и структурный фронтир обязателен. Решающий тест ценности графа.
  • Прямое сравнение с ToG-3 / HippoRAG-2 на одних кейсах по трём осям: полнота, false-completion rate, стоимость на кейс.
  • Обученная проекция связей по типам отношений — поднять полноту локального слоя без контроллера.
  • Векторизация поиска (numpy/FAISS) под корпусные масштабы.

Итог

  • Полнота доказательств — измеримая, отдельная от точности задача, и мы построили для неё воспроизводимый бенчмарк с парной статистикой.
  • Без контроллера графовая связанность — единственный training-free механизм, пробивающий плато полноты (0.21 → 0.30).
  • С контроллером gap-driven контур достигает 0.70 zero-shot — рядом с supervised SOTA; типизированный граф даёт ×1.8 экономию токенов.
  • Каждая цифра — с парным тестом, конфигом и манифестом. Границы метода найдены и опубликованы нами самими.
